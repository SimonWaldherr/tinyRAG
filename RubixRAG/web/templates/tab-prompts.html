Skills

Jeder Skill wird nur dann in den Prompt eingefügt, wenn eines seiner Tags in der Frage vorkommt. Deaktivierte Skills werden nie verwendet.

Passt mehr als ein Skill, werden alle passenden nacheinander an den System-Prompt (index.md bzw. agent.md) angehängt, relevantester zuerst — es wird nie nur einer ausgewählt. Ein Tag muss nicht exakt im Wortlaut der Frage stehen: eine einfache Pluralerkennung berücksichtigt auch naheliegende Formen (z. B. Tag "handschuh" passt auch auf "Handschuhe").

💡 Hinweise zum Verfassen guter Skills
  • Tags als Grundform (Singular) wählen — "Handschuhe" im Fragetext passt automatisch auch auf den Tag "handschuh". Trotzdem hilft es, gängige Synonyme zusätzlich als eigene Tags aufzunehmen (z. B. sowohl "reklamation" als auch "beschwerde").
  • Wenige, spezifische Tags schlagen viele, generische — ein Tag wie "frage" oder "produkt" würde bei fast jeder Anfrage feuern und den Prompt unnötig aufblähen.
  • Der Skill-Inhalt sollte knapp und faktenorientiert sein (Tabellen, Listen, konkrete Regeln) — er wird bei jeder passenden Frage komplett mitgeschickt und kostet entsprechend Kontext/Tokens.
  • Mit der Testfrage unten vor dem Speichern prüfen, ob die gewählten Tags tatsächlich wie erwartet greifen.

Abteilungs-Regeln (department_rules.json)

Ordnet die AD-Attribute department/title beim Login auf Abteilungs-Codes zu (siehe Einstellungen -> "Zugriffskontrolle je Quelltyp"). JSON-Array aus Objekten {"regex": "...", "code": "..."}, ausgewertet in Reihenfolge — die erste passende Regel gewinnt. Ohne eigene Datei gelten eingebaute Standard-Regeln (siehe department.go). Änderungen wirken erst beim nächsten Login der jeweiligen Person, nicht rückwirkend für bereits angemeldete Sitzungen.
